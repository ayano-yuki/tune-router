# TuneScope

ファインチューニングを用いて、質問の内容に応じた最適な AI モデル選択の精度向上を目指すプロジェクト。

## 目的

複数の専門 AI モデルを用意した環境では、すべての質問を最大モデルへ投げるよりも、質問の種類に応じて適切なモデルを選ぶ方が、精度・速度・GPU メモリ効率のバランスを取りやすい。

TuneScope では、入力された質問を分類し、コード、CVE/ログ、IaC/文章などの用途に応じた専門モデルへ振り分けるための小さな判定モデルを学習する。

## 想定構成

| 役割 | 候補モデル | 想定 VRAM |
| --- | --- | --- |
| 判定用モデル | DeBERTa / Qwen2.5-0.5B | 約 0.5GB - 1GB |
| 専門モデル 1: コード | Qwen2.5-Coder 7B (4-bit) | 約 5GB |
| 専門モデル 2: CVE/ログ | Llama-3.1 8B (4-bit) | 約 6GB |
| 専門モデル 3: IaC/文章 | Qwen2.5 14B (4-bit) | 約 10GB |
| 会話文脈・同時リクエスト用 | KV Cache / 余白 | 約 20GB - 30GB |

## 今回のスコープ

今回の開発では、専門モデル自体の追加学習は行わず、判定用モデルの学習に集中する。

理由は以下の通り。

- 専門モデルは既存の高性能モデルを 4-bit 量子化で利用できる
- 性能改善のボトルネックは、質問に対して適切なモデルを選べるかにある
- 判定用モデルは小さく、学習・評価・改善サイクルを回しやすい
- 専門モデルを個別に学習するより、必要なデータ量と GPU コストを抑えられる

そのため、まずは質問データに対して「どの専門モデルに渡すべきか」というラベルを付与し、判定用モデルをファインチューニングする。

## 学習タスク

入力:

```text
Kubernetes の Deployment で readinessProbe が失敗する原因を調べたい
```

出力:

```text
iac_text
```

想定ラベル:

| ラベル | 用途 |
| --- | --- |
| `code` | プログラミング、デバッグ、実装支援 |
| `security_log` | CVE、脆弱性調査、ログ解析 |
| `iac_text` | Terraform、Kubernetes、設定ファイル、技術文書 |
| `general` | 一般質問、雑談、分類不能な入力 |

## 評価指標

- 分類精度
- クラス別 F1 スコア
- 誤った専門モデルへ送った割合
- 最大モデルへ逃がした割合
- 応答品質と推論コストのバランス

## 今後の拡張

- 学習データの自動生成と人手レビュー
- 不確実性が高い入力を大きなモデルへフォールバックする仕組み
- 実際の応答品質を使った振り分け評価
- 同時リクエスト時の GPU メモリ使用量の検証
- 専門モデル構成の追加・入れ替え
